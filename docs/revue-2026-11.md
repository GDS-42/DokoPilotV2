# Revue de sécurité — novembre 2026

Revue complète du dépôt à la version 0.2 : exposition, accès, clés et secrets, stockage et
sauvegardes, pile Dokos, Forgejo et contexte, poste de travail, installateur. Ce document dit ce
qui a été trouvé, ce qui est corrigé, ce qui reste à faire, et ce qui a été vérifié ou non. Les
choix qui en découlent sont consignés dans [decisions.md](decisions.md) (D-33).

## Méthode

Six relectures indépendantes, une par domaine, ont lu l'ensemble des fichiers de leur périmètre.
Chaque constat a ensuite été vérifié dans le code avant d'être corrigé ; la plupart des
corrections ont un test de non-régression **qui échoue sur l'ancien code** : 28 tests unitaires,
11 cas de configuration et 39 contrôles des scripts de sauvegarde sont nouveaux. Un constat que
la vérification n'a pas confirmé a été écarté (la garde « courriel » de Claude Code bloquait
déjà les entrées malformées).

## Ce qui reste à faire

Ces points n'ont pas été corrigés : ils touchent la pile réelle (Dokos, Forgejo, Docker) et ne
doivent pas l'être sans `make test-stack`, `tests/context/run.sh` et `make test-system`.

### À traiter avant une mise en production

1. **L'étiquette `v0.2.0` n'existe pas.** Le démarrage rapide du README télécharge
   `…/v0.2.0/install.sh` : tant que l'étiquette n'est pas posée, la commande échoue.
2. **Identifiant 1000 partagé avec les conteneurs.** Reproduit avec Docker : un compte du serveur
   d'uid et gid 1000 lit les fichiers et l'environnement des conteneurs sans sudo
   ([securite.md](securite.md#comptes-du-serveur-et-conteneurs)). Lancer le conteneur avec un
   groupe dédié (`user: "1000:<gid>"`) ferme cet accès dans l'essai ; à valider avec les images
   de Dokos et de Forgejo, ou remplacer par `userns-remap`. Non essayé sous AppArmor.
3. **Pièces jointes des documents validés.** D'après la lecture du code de Dokos, le rôle
   automatique `All` donne à l'assistant le droit de supprimer un fichier attaché à un document
   sur lequel il a le droit d'écriture, même validé (la facture PDF d'un fournisseur). À
   confirmer sur une pile réelle ; correction proposée : la propriété `protect_attached_files`
   sur les types de documents comptables, avec un test.
4. **Le jeton de l'assistant est une clé d'API générale.** Hors du serveur MCP, des points
   d'entrée de Dokos ne vérifient que le droit d'écriture (clôture ou réouverture de commandes
   validées) ou acceptent l'envoi d'un courriel dès qu'un compte d'envoi existe. Correction
   proposée : une règle du proxy qui n'admet ce jeton que sur le point d'entrée MCP, et un
   signalement à Dokos.
5. **Mise à jour de Dokos** : les services redémarrent sur la nouvelle image avant la migration,
   sans sauvegarde imposée. Sauvegarder d'abord, migrer services arrêtés.

### À traiter ensuite

- Dokos : les rapports promis aux compétences (balance, grand livre) sont refusés au rôle de
  l'assistant ; le temps réel (Socket.IO) ne peut pas s'authentifier depuis le réseau interne ;
  un profil de rôles peut redonner un rôle retiré ; pas de limite de mémoire ni `cap_drop` dans
  Compose ; le chargeur de démonstration ne se protège que par Ansible.
- Forgejo : renommer l'identifiant d'une personne échoue tant que l'ancien compte garde son
  courriel ; à la réutilisation d'un identifiant, la nouvelle personne hérite de l'ancien dépôt
  personnel (signalé par `install`, à archiver automatiquement) ; les équipes écrivent dans le
  wiki, hors de la branche protégée.
- Système : pas de chaîne `forward` propre (à vérifier avec Docker) ; les règles sudo sans mot de
  passe sont retirées par motif, pas par effet ; les mises à jour automatiques prennent aussi les
  versions majeures de Docker et de Tailscale ; la clé Tailscale reste dans les secrets après
  usage.
- Poste : la marque « exposée » se perd sur une session dupliquée de Claude Code ; la version
  minimale de Claude Code n'est pas vérifiée ; les serveurs MCP de messagerie et d'agenda sont
  résolus par `uvx` et `npx` au premier lancement, sans empreintes.
- Installateur : en mode distant, une clé SSH au nom non standard ou protégée par une phrase de
  passe fait échouer la vérification ; une réponse ne se corrige pas sans tout reprendre.

### Améliorations proposées

- Un mode « restauration seule » pour un serveur d'essai (aucune sauvegarde nocturne).
- Une commande qui affiche la fiche de secours (clé age, mot de passe et adresse des
  sauvegardes) à ranger hors des machines, et une rotation outillée des destinataires.
- Dans l'assistant : corriger une étape depuis le récapitulatif, joindre le serveur dès la
  première étape, conseiller `tmux` quand l'installation est lancée par SSH.
- Séparer les outils de développement (linters) de ce que `make setup` installe chez un client.

## Ce qui a été vérifié

| Vérification | Résultat |
| --- | --- |
| `make lint` (yamllint, ansible-lint profil production, shellcheck, syntaxe Python) | Aucun défaut |
| `make test` | 29 tests de la CLI, 30 de l'assistant, 16 des provisionnements, 40 cas de configuration, 64 contrôles du harnais, 39 contrôles des scripts de sauvegarde contre un vrai dépôt restic : tous réussis |
| Assertion SSH, expressions de `check`, nom d'application Forgejo | Exécutées à part, avec le vrai `sshd` et Ansible |
| `make test-system`, `test-installer`, `test-local-mode`, `test-e2e`, `test-site`, `test-stack`, `tests/context/run.sh` | **Non lancés** : l'environnement de la revue n'atteignait ni Ansible Galaxy, ni les dépôts Debian, ni les registres de Dokos et de Forgejo |

Les collections Ansible venaient du paquet `ansible` de PyPI (`community.general` 13.5.1, hors de
la plage `>=14` du dépôt). **Avant de fusionner, lancez sur un poste** `make setup`, `make ci`,
`tests/context/run.sh` et `make test-stack` : les changements des rôles `ssh`, `proxy`, `backup`,
`forgejo`, `dokos_config` et des playbooks ne sont couverts que par ces tests.
