# Revue de sécurité — novembre 2026

Revue complète du dépôt à la version 0.2 : exposition, accès, clés et secrets, stockage et
sauvegardes, pile Dokos, Forgejo et contexte, poste de travail, installateur. Ce document dit ce
qui a été trouvé, ce qui est corrigé, ce qui reste à faire, et ce qui a été vérifié ou non. Les
choix qui en découlent sont consignés dans [decisions.md](decisions.md) (D-33).

## Méthode

Six relectures indépendantes, une par domaine, ont lu l'ensemble des fichiers de leur périmètre.
Chaque constat a ensuite été vérifié, dans le code puis sur les piles réelles (Dokos, Forgejo,
Debian 13), avant d'être corrigé ; la plupart des corrections ont un test de non-régression **qui
échoue sur l'ancien code** : 28 tests unitaires, 11 cas de configuration, 39 contrôles des
scripts de sauvegarde, et de nouveaux contrôles dans les tests des piles réelles. La
vérification a aussi écarté ou réduit des constats : la garde « courriel » de Claude Code
bloquait déjà les entrées malformées, et les conteneurs de Dokos n'étaient pas lisibles par un
compte d'uid 1000 (seul celui de Forgejo l'était).

## Ce qui reste à faire

### À traiter avant une mise en production

1. **L'étiquette `v0.2.0` n'existe pas.** Le démarrage rapide du README télécharge
   `…/v0.2.0/install.sh` : tant que l'étiquette n'est pas posée sur la branche principale, la
   commande échoue. C'est un geste du propriétaire du dépôt.
2. **Le jeton de l'assistant est une clé d'API générale** (d'après la lecture du code de Dokos,
   non essayé). Hors du serveur MCP, des points d'entrée de Dokos ne vérifient que le droit
   d'écriture (clôture ou réouverture de commandes validées) ou acceptent l'envoi d'un courriel
   dès qu'un compte d'envoi existe. Ne configurez pas de compte de courriel sortant dans Dokos
   sans y avoir réfléchi ; à signaler à Dokos, et à fermer par une règle devant Dokos qui
   n'admette ce jeton que sur le point d'entrée MCP.
3. **Mise à jour de Dokos** : les services redémarrent sur la nouvelle image avant la migration,
   sans sauvegarde imposée. D'ici là, lancez `bin/dokopilot backup <client>` avant toute mise à
   jour, comme le dit [exploitation.md](exploitation.md).
4. **Les tests d'installation en conteneur** (`make test-installer`, `test-local-mode`,
   `test-e2e`, `test-site`) n'ont pas pu être lancés pendant la revue : lancez-les avant de
   fusionner (voir « Ce qui a été vérifié »).

### À traiter ensuite

- Dokos : les rapports « Comptes clients » et « Registre des achats » sont désormais permis à
  l'assistant mais échouent dans l'agrégation de Dokos AI (à signaler ; les compétences donnent
  la méthode de repli) ; le temps réel (Socket.IO) ne peut sans doute pas s'authentifier depuis
  le réseau interne ; un profil de rôles peut redonner un rôle retiré ; pas de limite de mémoire
  ni `cap_drop` dans Compose ; le chargeur de démonstration ne se protège que par Ansible.
- Forgejo : renommer l'identifiant d'une personne échoue tant que l'ancien compte garde son
  courriel ; à la réutilisation d'un identifiant, la nouvelle personne hérite de l'ancien dépôt
  personnel (signalé par `install`, à archiver automatiquement) ; les équipes écrivent dans le
  wiki, hors de la branche protégée.
- Système : pas de chaîne `forward` propre (à vérifier avec Docker) ; les règles sudo sans mot de
  passe sont retirées par motif, pas par effet ; les mises à jour automatiques prennent aussi les
  versions majeures de Docker et de Tailscale ; la clé Tailscale reste dans les secrets après
  usage ; un compte d'uid 1000 peut arrêter (pas lire) les processus des conteneurs.
- Poste : la marque « exposée » se perd sur une session dupliquée de Claude Code ; la version
  minimale de Claude Code n'est pas vérifiée ; les serveurs MCP de messagerie et d'agenda sont
  résolus par `uvx` et `npx` au premier lancement, sans empreintes.
- Installateur : en mode distant, une clé SSH au nom non standard ou protégée par une phrase de
  passe fait échouer la vérification ; une réponse ne se corrige pas sans tout reprendre.

### Améliorations proposées

- Un mode « restauration seule » pour un serveur d'essai (aucune sauvegarde nocturne).
- Une commande qui affiche la fiche de secours (clé age, mot de passe et adresse des
  sauvegardes) à ranger hors des machines, et une rotation outillée des destinataires.
- Dans l'assistant : corriger une étape depuis le récapitulatif, joindre le serveur dès la
  première étape, conseiller `tmux` quand l'installation est lancée par SSH.
- Séparer les outils de développement (linters) de ce que `make setup` installe chez un client.

## Ce qui a été vérifié

| Vérification | Résultat |
| --- | --- |
| `make setup` | Réussi, collections Ansible dans les plages épinglées (`community.general` 14.0.1) |
| `make lint` (yamllint, ansible-lint profil production, shellcheck, syntaxe Python) | Aucun défaut |
| `make test` | 29 tests de la CLI, 30 de l'assistant, 16 des provisionnements, 40 cas de configuration, 64 contrôles du harnais, 39 contrôles des scripts de sauvegarde contre un vrai dépôt restic : tous réussis |
| `make test-system` (rôles système, conteneur Debian 13 avec systemd) | Tous les contrôles réussis : amorçage, deux passages dont le second sans changement, simulation, gardes anti-verrouillage, retrait d'un compte, Tailscale |
| `tests/context/run.sh` (Forgejo 17.0.1 réel) | 162 contrôles réussis |
| `make test-stack` (pile Dokos réelle : installation, données, MCP, droits, sauvegarde et restauration) | 74 contrôles réussis |
| `make test-installer`, `test-local-mode`, `test-e2e`, `test-site` | **Non lancés** : ces tests installent des paquets depuis leurs conteneurs par un accès réseau direct, que l'environnement de la revue n'offrait pas (proxy HTTPS seulement) |

Deux particularités de l'environnement de la revue, sans effet sur le dépôt : Docker Hub y
limitait les téléchargements anonymes (un miroir du registre a servi), et l'horloge de la machine
a reculé d'une heure en cours de route, ce qui a fait échouer deux lancements avant qu'ils soient
repris. **Avant de fusionner, lancez sur un poste** `make ci`, `make test-installer`,
`make test-local-mode` et, si possible, `make test-e2e` : les changements de l'assistant et
d'`install.sh` n'ont été vérifiés que par leurs tests unitaires.
